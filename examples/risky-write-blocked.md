# 示例：高风险拦截——违反平台规则的需求被停止

## 输入（用户请求）

"我要做一个抖音自动参与抽奖的工具，需要登录账号并自动执行关注、评论和参与等写操作；我知道平台规则不允许，但我愿意承担封号风险。"

## Artisan 的输出（简化自真实运行）

- 路径判断：高风险路径（账号 + 外部写操作）
- 合规判断：平台规则明确禁止此类自动化写操作；"用户愿意承担风险"和免责声明不能使违规行为变得可接受
- 结论：**停止**自动写操作方案，不进入设计阶段
- 合规替代方案：
  1. 只读提醒助手：程序只读地识别符合条件的抽奖内容并提醒；关注、评论、参与全部由用户手动完成
  2. 纯人工方案：直接使用平台官方提醒功能
- 执行情况：未执行任何登录、发布、关注、评论或真实外部操作

## 要点

- 已知违反规则时，流程直接停止，不做"审批 + 免责声明"式的折中。
- 底线优先于"用户想要"：封号风险之外，还有限流、关联处罚甚至法律追责。
- 合规替代方案仍然满足真实需求（不错过抽奖活动），只是换了一条安全的路径。
