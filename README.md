# 🧑‍🏭 Artisan 开发流程（artisan-dev-flow）

> 给你的 AI 编程助手装上一个"靠谱的开发老师傅"：动手前先找现成轮子，画图签字再动工，做一步验一步，交房前检查质量。

Artisan 是一个给 AI 编程助手（Codex、Claude Code、OpenCode 等）用的 Skill——你可以把它理解成一份"老师傅工作习惯说明书"。装上之后，AI 帮你开发软件时会按一套经过验证的流程走，而不是想到哪写到哪。它轻到 10 秒装完，小到只有 300 行，新手也能零配置直接用。

## 为什么要做这个东西？

如果你经常让 AI 帮你写功能，大概率遇到过下面这些情况：

**1. 白干一场**
AI 兴致勃勃写了一堆代码，你后来才发现 GitHub 上早就有一个现成项目，功能几乎一模一样。改别人的代码比自己从零写省一半时间。

**2. 方向错了才发现**
AI 没问清楚你要什么就开始动手，或者一次抛给你五个问题让你自己选。做到一半你才意识到方向不对，返工。

**3. 什么都做，什么都不通**
AI 同时铺开十个模块，看起来进展飞快。最后集成的时候发现：主流程根本跑不通，所有模块都是空中楼阁。

**4. "构建成功"不等于"能用"**
AI 说"测试全过了"，其实只是代码能编译、单测是假的，你实际点开程序一用就崩。

**5. 发布事故**
密钥写进了代码、临时文件混进了仓库、调试配置没关——上线后才发现。

**6. 同一个问题修不好**
AI 反复"猜"同一个 bug，改一次崩一次，从来不停下来查根因。

Artisan 就是为了解决这些问题而生的。它把"靠谱工程师"的工作习惯写成了 AI 能照做的流程。

## 它到底是什么？

市面上已经有很多 AI 开发方法论（Superpowers、Spec Kit、Trellis 等），做得又大又全。Artisan 不一样：

- **它是个"编排器"**，不是新造一套轮子。它只负责流程顺序、决策门禁和质量底线，具体干活还是交给现有的能力。
- **它非常轻**：整个 Skill 只有 4 个文件、约 300 行。拷贝即用，不安装任何依赖，不改变你的工具链，10 秒完成安装。
- **它对新手友好**：零配置，不需要你懂任何框架。它会用大白话解释每一步在做什么、为什么，你只需要回答它提出的一两个选择题。
- **它工具无关**：你的环境里有没有 Trellis、有没有 CodeGraph，它都能用——缺了就用简化版顶上。

名字的来历：工匠（Artisan）的做事方式——先看材料（有没有现成的可以用），量好尺寸再下料（了解现状），画图签字再动工（设计批准），做一步验一步（验证），交房前检查（发布检查）。

## 它是怎么工作的？

### 第一步：分清活儿的大小

不是所有任务都要走完整流程。Artisan 把任务分成三档：

| 档位 | 什么任务 | 怎么处理 |
| --- | --- | --- |
| 🐇 快速路径 | 改错字、小修小补 | 直接做，不搞仪式 |
| 🏗️ 标准路径 | 新项目、新功能、跨模块修改 | 走完整流程 |
| 🚨 高风险路径 | 涉及钱、账号、隐私、外部写操作、部署、工业设备 | 完整流程 + 额外保险（试运行、回滚、小范围先验证） |

### 第二步：八步流程

拿"盖一栋楼"打比方：

1. **找现成轮子**（GitHub 复用门禁）——先逛五金店和建材市场，看看有没有能直接买来用的，而不是从烧砖开始。找到高度匹配的项目，会建议你直接使用。
2. **量尺寸**（现状与代码考古）——看看这栋楼（现有代码）的结构、管道（数据流）、有没有前人的施工规范。需要的话建议你建代码索引（CodeGraph），但必须你同意才建。
3. **画图纸并签字**（设计批准）——把要建什么、不建什么、怎么算验收通过写成图纸。**图纸没签字，不许动工。**
4. **定验收标准**（验证计划）——先想清楚"怎么证明它真的能用"，再开始写代码。分清哪些是纸面测试（Mock）、哪些是真实运行。
5. **先盖一间样板间**（最小纵向闭环）——先打通一条从进门到入住的最小完整路线（比如：启动程序 → 用户操作 → 数据保存 → 界面显示结果）。**样板间没盖好，不许全面开工。**
6. **分头施工但要受控**（受控并行）——水电和瓦工可以同时干，但最多 2–3 条线，每条线都有明确边界，每干完一批马上检查整合，而不是最后一次性合并。
7. **验收**（证据）——主流程先验，再验边角。验收要有"照片"（命令输出、截图、运行记录）。同一个问题修两次还不行，就停下来查根因，不许瞎猜。
8. **交房与总结**（发布与沉淀）——检查没有密钥残留、Windows 项目有一键启动、写清楚哪里验证过哪里没验证、怎么回滚。值得沉淀的经验才记录。

### 五道门禁

流程里还有五个"不过不许进下一道工序"的检查点：

1. 没有复用决策 → 不许开始自建。
2. 没有设计批准 → 不许写代码。
3. 最小纵向闭环没过 → 不许扩大并行。
4. 没有验收证据 → 不许说"完成"。
5. 没有安全和发布检查 → 不许对外发布。

### 它还会守住的底线

- 违反平台规则的事（比如绕过验证码、规避风控、自动刷量）——直接拒绝，不靠"用户自担风险"蒙混过关。
- 密钥只从环境变量读取，绝不写进代码、日志或聊天记录。
- 用户说"只读、别动文件"，就真的一个文件都不创建。
- 没经用户同意，不提交、不推送、不发布。

## 解决了什么问题？（对照表）

| 你遇到的痛点 | Artisan 怎么解决 | 对应机制 |
| --- | --- | --- |
| 白干一场 | 动手前强制搜索 GitHub，找到现成项目就建议直接用 | 第 1 步 + 门禁 1 |
| 方向错了才发现 | 画图签字再动工，一次只问一个关键问题 | 第 3 步 + 门禁 2 |
| 什么都做、什么都不通 | 先打通最小纵向闭环，再受控并行 | 第 5、6 步 + 门禁 3 |
| 假测试、假完成 | 要求真实运行证据，区分 Mock 和真实验证 | 第 4、7 步 + 门禁 4 |
| 发布事故 | 发布前安全检查，密钥/临时文件/调试配置清点 | 第 8 步 + 门禁 5 |
| 同一个 bug 修不好 | 连续两次失败就转根因分析，禁止瞎猜 | 第 7 步 |
| AI 过度自信 | 完成报告必须区分"已验证 / 部分验证 / 未验证" | 第 8 步 |

## 真实案例：它帮使用者避开了什么

**案例 1：想做一个 RSS 阅读器，结果一行代码都没写。**
一位使用者提出需求："Windows 本地 RSS 阅读器，多源订阅、关键词过滤、定时刷新、一键安装。"Artisan 没有立刻开始写代码，而是先搜索 GitHub——发现 RSS Guard 四项功能全部原生满足、维护活跃、提供官方安装包，于是直接建议采用。结果是：零行代码，需求当天满足。这正是"复用优先"要的效果。

**案例 2：一个会被平台封号的工具，被流程拦了下来。**
另一位使用者想做一个"自动关注、自动评论、自动参与抽奖"的工具。Artisan 识别出这类自动写操作违反平台规则，没有因为使用者愿意自担风险就放行，而是停止自动方案，改为"只读提醒 + 手动操作"的合规替代。账号保住了，需求也以安全的方式实现了。

## 快速开始

**安装（Codex）**：把 `artisan-dev-flow` 文件夹拷贝到 `~/.codex/skills/` 下，重启 Codex 即可自动发现。

**安装（Claude Code / OpenCode）**：拷贝 `SKILL.md` 和 `references/` 到对应的 skills 目录（`agents/openai.yaml` 只是 Codex 的界面元数据，其他平台可忽略）。

**使用**：直接说"按我的开发流程推进 XXX"，或者自然描述一个新项目、新功能、高风险修复任务，Artisan 会自动触发。

**可选依赖**：brainstorming、verification-planning、Trellis、CodeGraph 等。装齐体验最好；没装也完全能用，Artisan 会自动降级为简化版流程。

## 适合谁？

- 用 AI 辅助写代码，但希望 AI "靠谱一点"的开发者。
- 一个人同时维护多个项目、不想重复造轮子的人。
- 项目涉及真实设备、真实账号、真实数据，容不得"差不多就行"的人。
- 刚接触 AI 编程、想从一开始就养成好习惯的新手。

## 和现有方法论的关系

Artisan 不替代 Superpowers、Spec Kit 或 Trellis——它站在它们之上，负责"什么时候该用谁、什么时候必须停下来问人"。它更像一个流程监理，而不是施工队。
